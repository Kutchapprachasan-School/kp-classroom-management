# ADR-004: สถาปัตยกรรมฐานข้อมูลร่วม (Shared Supabase), การเก็บเช็คชื่อแบบ Exception-Only รองรับเด็กย้ายเข้าใหม่, นโยบายนับเวลาเรียน (ลาป่วย/ลากิจ) และระบบเยี่ยมบ้าน นร.01 เชื่อมต่อระบบ CCT กสศ. (`cct.eef.or.th`) อัตโนมัติ

## สถานะ (Status)
**APPROVED (อนุมัติจากการ Grill-Doc รอบที่ 3 - 24 กันยายน 2569)**

---

## 1. การตัดสินใจเชิงสถาปัตยกรรม (Architectural Decisions)

### 1.1 การบันทึกเช็คชื่อแบบ Exception-Only + Session Header และการป้องกันข้อมูลเพี้ยนเมื่อมีนักเรียนย้ายเข้าใหม่ (`Q1 = Option A`)
- **โครงสร้างการเก็บข้อมูลประหยัดโควตา 90%:**
  - ตาราง `cls_attendance_sessions`: บันทึกหัวคาบเรียน 1 แถวต่อคาบ (ระบุ `classroom_id`, `course_id`, `session_date`, `period_no`) เพื่อเป็นหลักฐานว่าครูได้เช็คชื่อคาบนี้แล้ว
  - ตาราง `cls_attendance_exceptions`: บันทึกเฉพาะนักเรียนที่ **ไม่ได้มาเรียนปกติ** (`ABSENT` ขาด, `LATE` สาย, `SICK_LEAVE` ลาป่วย, `PERSONAL_LEAVE` ลากิจ, `ACTIVITY` กิจกรรม)
- **การป้องกันประวัติเพี้ยนกรณีมีนักเรียนย้ายเข้าใหม่กลางเทอม (`Mid-Term Transfer Invariant`):**
  - ตาราง `cls_enrollments` บังคับเก็บฟิลด์ `enrolled_at` (วันที่เริ่มเข้าเรียนในห้องนี้) และ `transferred_attended_periods` (จำนวนคาบเรียนสะสมที่โอนมาจากโรงเรียนเดิม)
  - สูตรคำนวณจำนวนคาบเรียนทั้งหมดของนักเรียนรายบุคคล (`Total Valid Sessions for Student S`):
    $$\text{ValidSessions}(S) = \text{COUNT}\Big(\text{session} \in \text{cls\_attendance\_sessions} \;\Big|\; \text{session.date} \ge S.\text{enrolled\_at} \;\land\; (\text{session.date} \le S.\text{withdrawn\_at})\Big)$$
  - **ผลลัพธ์:** คาบเรียนทั้งหมดที่เกิดขึ้น **ก่อนวันที่นักเรียนย้ายเข้า (`session.date < enrolled_at`) จะถูกตัดออกจากการคำนวณของเด็กคนนั้นโดยอัตโนมัติ** ทำให้นักเรียนเข้าใหม่ไม่มีทางได้คาบเรียนเกินจริง หรือถูกนับว่าขาดเรียนย้อนหลัง

---

### 1.2 การแยกใบลานักเรียนออกจาก E-Leave ของครู และการตั้งค่าสูตรคำนวณเวลามาเรียน (`Q2 = Option A + Configurable Leave Policy`)
- **การแยกขอบเขตระบบการลา:**
  - ระบบ **E-Leave (`eleave_*`)** ใช้สำหรับการลาของ **ข้าราชการครูและบุคลากร** เท่านั้น
  - การลานักเรียน (**ลาป่วย / ลากิจของนักเรียน**) จัดเก็บในตาราง `cls_student_leaves` ของ **ระบบจัดการชั้นเรียน** โดยตรง เพื่อให้นักเรียน/ผู้ปกครองยื่นใบลาผ่านพอร์ทัลนักเรียน และให้ครูที่ปรึกษา/ครูประจำวิชาอนุมัติได้ในที่เดียว
- **การตั้งค่านโยบายการนับเวลาเรียน (`Attendance Leave Calculation Policy`):**
  - เพิ่มการตั้งค่าระดับรายวิชา/สถานศึกษา ให้ครูเลือกสูตรการนับเวลาเรียนเพื่อพิจารณาสิทธิ์สอบ (80% / มส.) ได้ 2 รูปแบบ:
    1. **`EXCLUDE_LEAVE_FROM_ATTENDED` (มาตรฐานเข้มงวด):** นับเฉพาะคาบที่ตัวนักเรียนอยู่เรียน (`มาเรียน + มาสาย + กิจกรรม`) เป็นเวลาเข้าเรียน ส่วน `ลาป่วย/ลากิจ` นับแยกเพื่อใช้ประกอบการผ่อนผัน
    2. **`INCLUDE_APPROVED_LEAVE_AS_ATTENDED` (โหมดนับรวมวันลาป่วย/ลากิจที่อนุมัติแล้วเป็นเวลามาเรียน):** นำจำนวนคาบที่ `ลาป่วย` และ/หรือ `ลากิจ` (ที่มีใบลาอนุมัติ) มารวมเป็นเวลาเข้าเรียน เพื่อคุ้มครองนักเรียนที่เจ็บป่วยมีใบรับรองแพทย์ไม่ให้ติด `มส.` อัตโนมัติ

### 1.3 สิทธิ์การเข้าถึงข้อมูลเยี่ยมบ้าน (Tiered RBAC) และการเก็บรูปภาพ/ลายเซ็น (`Q3 = Option A`)
- บังคับเก็บรูปถ่ายที่พักอาศัย (นอกบ้าน/ในบ้าน) และไฟล์ลายเซ็นดิจิทัลเป็น Object Storage URL (`Supabase Storage`) เท่านั้น ห้ามเก็บ Base64 ขนาดใหญ่ลงตารางฐานข้อมูลหลัก
- จำกัดสิทธิ์การดูข้อมูลเชิงลึกตามแบบ **นร./กสศ.01** (รายได้รายคน, เลขบัตรประชาชนสมาชิกครัวเรือน, ผล SDQ) เฉพาะ **ครูที่ปรึกษา, ฝ่ายแนะแนว/ทุน กสศ. และผู้บริหาร** ส่วนครูประจำวิชาเห็นเฉพาะป้ายสถานะการดูแลช่วยเหลือ

---

### 1.4 สถาปัตยกรรมระบบเยี่ยมบ้านตามแบบ **นร./กสศ.01 (ฉบับปรับปรุง 6 มีนาคม 2569)** และระบบ Auto-Sync เข้าสู่เว็บ **CCT กสศ. (`https://cct.eef.or.th`)**
- **โครงสร้างข้อมูลครบ 10 หมวด (5 หน้า) ตามฟอร์ม นร./กสศ.01 เป๊ะ 100%:**
  1. ข้อมูลนักเรียน, เลข 13 หลัก/รหัส G, สถานภาพครอบครัว (7 สถานะ), ผู้ปกครอง และสิทธิ์สวัสดิการแห่งรัฐ
  2. ตารางสมาชิกในครัวเรือน (1–10 คน) พร้อมความพิการ/โรคเรื้อรัง และรายได้เฉลี่ยต่อเดือนแยก 5 ประเภท คำนวณ **รวมรายได้ครัวเรือน** และ **รายได้เฉลี่ยต่อคนต่อเดือน** อัตโนมัติ
  3. สถานะครัวเรือน: ภาระพึ่งพิง (5 ข้อ), การอยู่อาศัย, ลักษณะบ้านจากการสังเกตของครู (วัสดุพื้นบ้าน, ฝาบ้าน, หลังคา, ห้องส้วม), ที่ดินเกษตร, แหล่งน้ำดื่ม, แหล่งไฟฟ้า, ยานพาหนะ และของใช้ในครัวเรือน
  4. ข้อมูลครัวเรือนสถาบัน (กรณีอาศัยในสถานสงเคราะห์/วัด)
  5. การเดินทางไปโรงเรียน (วิธีเดินทาง, ระยะทางไป-กลับ กม., เวลา ชม.:นาที, ค่าเดินทาง/เดือน, เงินมาโรงเรียน/วัน)
  6. ที่ตั้งที่พักอาศัยปัจจุบัน + พิกัด GPS (`lat`, `lng`)
  7. ภาพถ่ายที่พักอาศัย 2 มุมบังคับ: **รูปที่ 1 นอกบ้าน (เห็นหลังคาและฝาผนังทั้งหลัง)** และ **รูปที่ 2 ภายในบ้าน (เห็นพื้นและบริเวณภายใน)**
  8–10. **ลายเซ็นดิจิทัล (Digital Signature Pad 4 ฝ่าย):** ลายเซ็นนักเรียน, ลายเซ็นผู้ปกครอง, ลายเซ็นครูผู้เยี่ยมบ้าน, และลายเซ็นเจ้าหน้าที่ของรัฐ/ผอ.โรงเรียน
- **กลไกการโอนข้อมูลอัตโนมัติเข้าสู่ระบบ CCT กสศ. (`EEF CCT Auto-Sync Engine`):**
  - รองรับ 2 โหมดการส่งข้อมูลขึ้น `https://cct.eef.or.th`:
    1. **Direct API / Auto-Fill Extension Script Generator:** สร้างชุดคำสั่ง JSON Payload + สคริปต์อัตโนมัติที่เมื่อครูเปิดหน้าเว็บ `cct.eef.or.th` ระบบจะกรอกตัวเลือก Checkbox/Radio ทั้ง 10 ข้อ, อัปโหลดรูปถ่ายบ้านทั้ง 2 รูป และแนบลายเซ็นรับรองให้ครบทุกช่องในคลิกเดียว
    2. **Official นร./กสศ.01 5-Page Printable Form:** พิมพ์หรือบันทึกร่างเอกสาร นร.01 ครบทั้ง 5 หน้าพร้อมลายเซ็นอิเล็กทรอนิกส์เพื่อเก็บเป็นหลักฐานระดับสถานศึกษา
