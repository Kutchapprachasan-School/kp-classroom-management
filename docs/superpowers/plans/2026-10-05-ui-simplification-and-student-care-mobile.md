# แผนการปรับปรุงระบบทั้งหมด: UI Simplification & Student Mobile-First Care System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ปรับปรุง UI ทั้งระบบให้เรียบง่าย ไม่ซับซ้อนตามหลัก "1 หน้า = 1 งานหลัก" (เช็คชื่อคาบเรียนเท่านั้น, แถวเช้าแยกไปหน้าหลักตามข้อ ก, รวมกรอกคะแนนที่หน้างานตามข้อ ข, คงเมนูข้อสอบและแผนการสอนตามข้อ ค) พร้อมปรับปรุง 3 หน้า Desktop ตามภาพ `media_1791103560376.png` และพัฒนาระบบดูแลช่วยเหลือนักเรียนแบบ Mobile-First 9 หน้าจอเป๊ะตามภาพ `media_1791103851054.jpg`

**Architecture:** 
- **ฝั่งครู (Teacher UI Simplification):** แยกหน้าที่ของแต่ละหน้าอย่างชัดเจน `TeacherOverviewView` ทำหน้าที่เช็คชื่อคาบเรียนอย่างเดียว (ซ่อน 4-mode switcher และตัดตารางส่งงานซ้ำซ้อนออก), หน้าหลัก (`TeacherGlobalDashboardView`) เป็นจุดเช็คแถวเช้าของครูที่ปรึกษา, `AssignmentManagementView` เป็น Single Source of Truth ในการสร้าง/ตรวจ/กรอกคะแนนงานทั้งหมด, `EndTermReadinessView` เป็นมุมมองสรุปผลการเรียนและกรอกคะแนนสอบกลาง/ปลายภาคเพื่อส่ง SGS, และคงเมนูข้อสอบ/แผนการสอนไว้เป็นเมนูแยก
- **ฝั่ง Desktop 3 หน้า:** ปรับปรุง `StudentMissionsView` (กิจกรรมรายสัปดาห์ + Leaderboard + Active Buff), `StudentTrophyView` (น้องเขียว pixel pet + สถิติความสุข/อาหาร + 6 เหรียญรางวัล), และ `StudentHomeVisitFormView` (Stepper 3 ขั้น ข้อมูลผู้ปกครอง/สภาพครอบครัว/สรุปผล)
- **ฝั่ง Mobile First นักเรียน/ดูแลนักเรียน 9 หน้า:** พัฒนา `StudentMobileCareView` ที่รองรับ 9 หน้าจอ (หน้าแรก, รายชื่อ 32 คน, ข้อมูลนักเรียน, บันทึกพฤติกรรม, ห้องรางวัลน้องเขียว, สุขภาพจิต 5 อารมณ์, แจ้งเตือน 3 ชิป, สถิติ ม.3/8, ตั้งค่า) พร้อม Bottom Nav 4 ปุ่ม และรองรับ Responsive ปรับขนาดให้เหมาะกับ Tablet/PC

**Tech Stack:** React 18, TypeScript, Tailwind CSS, Lucide React, LocalStorage / Mock Services, Vite

## Global Constraints

- ยึดหลัก **"1 หน้า = 1 งานหลัก = 1 ปุ่มหลัก"** ห้ามมีฟังก์ชันกรอกคะแนนหรือจัดการงานซ้ำซ้อนในหน้าเช็คชื่อ
- การเช็คแถวเช้าต้องแยกออกจากวิชาสอนตามข้อตัดสินใจ **ก.** ของผู้ใช้
- การกรอกคะแนนชิ้นงานต้องทำที่หน้า "งาน/มอบหมาย" ที่เดียวตามข้อตัดสินใจ **ข.** ของผู้ใช้
- เมนู "ข้อสอบกลาง/ปลายภาค" และ "แผนการสอน" ต้องคงเป็นเมนูแยกตามข้อตัดสินใจ **ค.** ของผู้ใช้
- ฝั่ง Mobile First ต้องถอดแบบ layout, สี (Forest Teal `#0C6D5B`, Mint), typography และ icon จากภาพ `media_1791103851054.jpg` ทั้ง 9 หน้าจอ
- ฝั่ง Desktop 3 หน้าต้องตรงตามภาพ `media_1791103560376.png`
- รักษาความเข้ากันได้กับระบบเดิม Build ผ่าน 0 TypeScript errors (`npm run build`)
