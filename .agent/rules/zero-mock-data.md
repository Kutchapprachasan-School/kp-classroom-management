# ZERO MOCK DATA & STRICT DATA INTEGRITY POLICY
# กฎเหล็ก: ห้ามใส่ข้อมูลจำลอง (Mock Data) โดยพลการ และห้ามคิดเอง ต้องถามก่อนเสมอ

==================================================
01. CORE PRINCIPLES (หลักการสำคัญสูงสุด)
==================================================

1. **Strict Zero Mock Policy (ห้ามใส่ Mock Data โดยพลการเด็ดขาด)**:
   - ห้ามสร้างหรือใส่ข้อมูลจำลอง (Mock Data, Dummy Data, Fake Fallback Objects/Arrays) เข้าสู่โค้ดเบสโดยพลการเป็นอันขาด
   - ห้ามแต่งชื่อนักเรียนจำลอง, ชื่อครูจำลอง, กิจกรรมปฏิทินสมมุติ, คาบเรียนสมมุติ, คะแนนสมมุติ หรือข้อมูลหลอกใดๆ ใน view, component หรือ service
   - หากยังไม่มีข้อมูลจริงในฐานข้อมูล (Neon / Supabase) หรือผู้ใช้ยังไม่ได้นำเข้า (Excel / SGS) ให้แสดงผลเป็น **Empty State** หรือ Array ว่าง `[]` เสมอ

2. **No Unilateral Assumptions (เลิกคิดเองว่ามันต้องมี)**:
   - ห้ามทึกทักคิดไปเองว่า "ต้องใส่ข้อมูลจำลองไว้ก่อนเพื่อให้ UI ดูไม่โล่ง" หรือ "ระบบควรมีข้อมูลเริ่มต้นเหล่านี้"
   - ห้ามใส่ hardcoded fallback เพื่อหลบ error หรือเอาใจการแสดงผลชั่วคราว
   - ถ้าข้อมูลเป็น 0 หรือว่าง ให้ปล่อยให้ระบบสะท้อนความจริง 100%

3. **Mandatory Pre-Approval for Data Addition/Removal (จะเพิ่มหรือลดข้อมูล ต้องถามก่อนเสมอ)**:
   - หากมีความจำเป็นต้องเพิ่มชุดข้อมูลใหม่, ปรับแต่ง Schema, ลบข้อมูลเก่า, เพิ่ม Default Values หรือ Seeding:
     **ต้องถามและขอการตัดสินใจจากผู้ใช้ก่อนดำเนินการทุกครั้ง (Ask before making changes)**
   - ห้ามทำการเพิ่มหรือลบข้อมูลใน Database หรือ Client State เองโดยไม่ได้รับการยืนยันอย่างชัดเจน

==================================================
02. PROHIBITED PATTERNS (ข้อห้ามเด็ดขาด)
==================================================

- ❌ **ห้าม Hardcoded Mock Arrays ใน Service / Component**:
  เช่น `const mockStudents = [...]`, `INITIAL_OCTOBER_EVENTS = [...]`, `dummyTeachers = [...]`
- ❌ **ห้าม Fallback ไปหา Mock Data เมื่อ API / Database ว่างเปล่า**:
  เช่น `const data = dbData.length > 0 ? dbData : mockData;` (ห้ามเด็ดขาด! ต้องใช้ `const data = dbData;`)
- ❌ **ห้ามสุ่มหรือ Generate ข้อมูลหลอกขึ้นมาแสดงผล**:
  เช่น สุ่มเลขที่นักเรียน, สุ่มคะแนนสอบ, สุ่มการเข้าเรียน
- ❌ **ห้ามลบหรือโยกย้ายข้อมูลจริงของผู้ใช้โดยไม่ถามก่อน**:
  ต้องมีการแจ้งเตือนและขอคำยืนยันเสมอ

==================================================
03. COMPLIANT PATTERNS (แนวทางปฏิบัติที่ถูกต้อง)
==================================================

1. **Clean Empty State**:
   - เมื่อไม่มีข้อมูล ให้แสดง UI Empty State ที่สุภาพ สะอาด ตาม Pastel Anime Design System เช่น "ยังไม่มีข้อมูล กรุณานำเข้าหรือเพิ่มข้อมูลใหม่" พร้อมปุ่ม Action
2. **Real Data Source of Truth**:
   - เชื่อมต่อและดึงข้อมูลจาก Neon PostgreSQL / Supabase หรือ LocalStorage ที่ผู้ใช้นำเข้าจริงเท่านั้น
3. **Graceful Zero Handling**:
   - จัดการกรณี `data.length === 0` ให้ถูกต้อง ไม่ให้โค้ดพังโดยไม่ต้องพึ่งพา Mock Data
4. **Transparent Communication**:
   - หากต้องการแนะนำให้มีข้อมูลตั้งต้น ให้เสนอเป็นทางเลือกต่อผู้ใช้ และถามความยินยอมก่อนเสมอ
